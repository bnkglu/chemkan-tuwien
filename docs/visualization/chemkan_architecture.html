Layer anatomy — live arithmetic every parameter lives at an activation φ; connections and operators are parameter-free

How to count the parameters every φ holds N basis weights · every layer holds nin×nout of them

The whole count rests on one sentence in the paper: a layer connecting nl inputs to nl+1 outputs has nl · nl+1 activation functions, and all the network's parameters live inside those activations. So counting is three steps:

1. activations per layer = nl × nl+1
2. params per activation = N  (the grid size, Eq. 11)
3. add θthermo = m scalars, if the energy equation is on
params = Σlayers (nl × nl+1 × N) + m·[thermo]

nμ does not enter the count. It only decides whether an activation's output is multiplied or added downstream — it adds no weights. That's the whole point of LeanKAN: MultKAN needs 20 activations where AddKAN and LeanKAN need 12 for the same 4→3 layer.

3 fixes1 derivation Corrections to the earlier walkthrough

1 · 36 conditions generated, 35 used for training

Earlier: “35 different initial combinations of temperature and equivalence ratio.”

Cantera generates data at all 36 combinations of initial temperature T₀ ∈ {950, 1000, 1050, 1100, 1150, 1200} K and equivalence ratio Φ. The [1150 K, Φ=1.3] case is withheld as unseen test data → 35 training sets. 35 is the training count, not the grid.

§II.D.2 (p.9). Note: the printed Φ list shows only five values, which conflicts with the stated “36” — an apparent typo. 6×6 matches the ChemNODE setup the authors deliberately mirror.

2 · nμ splits the inputs; every output does both operations

Earlier: output nodes are “either a multiplication part or an addition part,” and hidden nodes are “pure multiplication hubs.”

The paper defines nμ as “the multiplication hyperparameter that dictates the number of multiplication input nodes for layer l.” Each output node always computes both a product (Eq. 9) and a sum (Eq. 10) and adds them (Eq. 8). Here nμ = nl = 3, so the addition group is empty and each of the 9 outputs reduces to a product. Right answer, wrong reason — it's the degenerate case, not the rule. Also: the product is formed at the output node, over its 3 incoming activations. Flip the anatomy panel to Biodiesel (nμ=2) to watch both groups fire at once.

ChemKAN Eqs. 8–10 (p.5), nμ=3 at p.15 · LeanKAN §3.1–3.2

3 · Forward sensitivity + Adam are used in both stages

Earlier: “forward sensitivity in Stage 1” vs “the Adam optimizer updates the network in Stage 2.”

Both stages take dL/dθ through the stiff Tsit5 solve with forward sensitivity analysis — chosen over adjoint precisely because adjoint can fail on stiff chemistry — and Adam (lr = 2×10⁻³) throughout. What changes between stages is which parameters are trainable and how many states enter the loss (n* = 9, then n* = 10).

  • §II.BBaselines. DeepONet: branch(u₀) ⊙ trunk(t) → u, no integrator. ChemNODE: m+1 separate MLPs, each learning one gradient, trained in m+1 frozen stages with zero information sharing.
  • §II.CChemKAN: AddKAN (Eq. 7) and LeanKAN (Eqs. 8–10) layers, RBF activations (Eqs. 11–12), kinetic core (Eq. 13) + thermo superstructure (Eqs. 14–15), loss (Eq. 18), two-stage training, forward sensitivity, Tsit5, Adam @ 2×10⁻³.
  • §III.ACase 1 — biodiesel transesterification (TG→DG→MG→GL, 3 reactions), isothermal, 30 sampled points, 10⁴ epochs. Kinetics-only core, 4 hidden nodes, nμ=2, 3-pt grids, 156 params vs a 308-param DeepONet. ChemKAN wins testing loss at every size and plateaus instead of overfitting. Under 15% noise its error rises ~2× vs DeepONet's 5×, ending 4.4× lower. Neural scaling: 1.0 train / 0.6 test — read as saturated, not stalled.
